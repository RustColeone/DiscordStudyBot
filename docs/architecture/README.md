# The architecture page

`index.html` here is a browsable map of the code, made from the code itself. It starts at the whole system and goes
in: a module or folder, a file, a class (section by section when it is big), and finally one function, whose code
shows in the pane on the right. Every box can be clicked, and the search finds any file, class or function.

- `data.js` is generated by [`tools/architecture.py`](../../tools/architecture.py): Python's `ast` reads every file git
  tracks under `contracts/`, `core/`, `extensions/`, `plugins/`, `tools/` and `tests/`. It records each file's
  docstring, imports, classes, functions, which call which inside the file, and the source. Which slot each module
  fills is read from its `extension.py`. Only the core's boxes on the top map are named in the tool (`CORE_PARTS`,
  after [docs/core/ARCHITECTURE.md](../core/ARCHITECTURE.md)).
- **After every change, run `python tools/architecture.py` and commit `data.js` with the change.**
  `tests/test_architecture.py` fails while the page is out of date.
- `app.js` and `style.css` are the page; the charts are drawn by [Mermaid](https://mermaid.js.org/) 10.9.1, loaded
  from a CDN.

**To read it locally**, open `index.html` in a browser (the charts need the internet for Mermaid), or serve the folder:
`python -m http.server -d docs/architecture`.

**To publish it on GitHub Pages:** in the repository's Settings → Pages, choose "Deploy from a branch", the branch
`master` and the folder `/docs`. The page is then at `https://<owner>.github.io/DiscordStudyBot/architecture/`
(`docs/index.html` sends the site's root there; `docs/.nojekyll` serves the files as they are).
